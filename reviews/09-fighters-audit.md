## 二、贴身穿插：数据与判定

### 2.1 多近才会真的穿模（`clip` 探针）
把两人按不同间距摆好，逐网格算包围盒间隙（`meshGap` 为三个分离轴上的空隙，0 = 实体接触）：

| 设定的中心间距 | 躯干/头的最小间隙 | 全部网格（含四肢）最小间隙 | 部位 |
|---|---|---|---|
| 0.90 | 0.42 | 0.143 | footR-footR |
| 0.80 | 0.31 | 0.085 | footL-footR |
| 0.70 | 0.21 | 0.006 | footR-footL |
| 0.65 | — | **0** | shinL-footR |
| 0.60 | 0.11 | 0.21（换了一对） | footR-footR |
| 0.55 | 0.22 | 0.152 | footL-footR |
| 0.40 | 0.06 | 0.009 | footL-footR |
| 0.35 | — | **0** | chest-foreArmL |

**读数**：
- **躯干/头**要到中心距 ≈0.35~0.40m 才会互相接触；
- **四肢**（脚/小腿）在 0.65~0.70 就会先碰到 —— 这是"脚对脚"的近身站位，不是身体穿模。

### 2.2 实战里到底能贴多近（`fight` 探针，40 秒 6325 帧随机走位 + 出招）

| 指标 | 值 |
|---|---|
| 最近距离 | **0.547 m** |
| 5% 分位 | 1.217 m |
| 中位数 | 2.334 m |
| 低于 0.55 的帧 | 11 帧（**0.2%**） |
| **低于 0.40 的帧** | **0** |

**判定：正常对局中两个角色的躯干/头部不会互相穿插。** 0.55 的碰撞半径在躯干尺度上是够的。

### 2.3 fighters.js 里能做的（已做）
**受击让位**：`hitFlash(amount, fromDir)` 现在除了原有的击退位移（2.4·a m/s 衰减），还会记下"受击侧"，
让上半身在受击后的头几帧**朝被打的一侧让开 + 后仰**（`yieldRoll` / `yieldPitch`，指数衰减 6/s）。
效果：攻击方的拳头在视觉上"打进躯干"的概率降低，被击中有更明显的"受身"。

### 2.4 需要 combat.js 决策的部分（交回 Lead）
- 现在 0.55 的半径已经足够阻止躯干穿模；如果用户看到的是"手/脚互相穿过"，把半径提到 **0.70~0.75** 才能彻底消除，
  代价是近身范围被推远（SKILL_DATA 的 range 是 4~5.2，实测命中距离约 1.7m，还有余量，**技术上可行**）。
- 但这属于**手感取舍**（贴身连段会更难起手），我不越界改 combat.js —— 需要的话请 Lead 定，我可以配合复测。

## 三、待机 / 受击 / 过渡：改前改后

### 3.1 待机微动（`idle` 探针，6 秒静置，逐帧统计骨骼活动范围）

| 指标 | 改前 | 改后 |
|---|---|---|
| 骨盆上下（hips.y） | **0（完全静止）** | **0.0097 m** |
| 骨盆左右倾（hips.z） | 0.016 | **0.059 rad** |
| 躯干前后（core.x） | 0.025 | 0.212 |
| 头部左右（head.y） | 0.030 | 0.302 |

做法：把原来"站着不动时只呼吸"扩成**重心转移循环** —— 骨盆左右倾/旋转 + 上身反向 + 膝关节交替屈伸
（腿在"撑住"身体而不是两根棍），幅度按角色占屏 16% 的可读性给。走起来时这一层自动让位给行走层。

### 3.2 受击区分度与回 idle 过渡（`hits` 探针）

姿态幅度 = 11 根骨骼 |x|+|y|+|z| 之和（idle 基线 0.97~1.26）：

| 动作 | 姿态幅度 | 回 idle 单次 update 最大跳变 |
|---|---|---|
| hit_light | 4.95 | **0.14 rad** |
| hit_heavy | 7.28 | **0.136 rad** |
| knockback | 6.96 | **0.133 rad** |
| down | 12.02 | **0.131 rad** |

- **区分度**：轻击 ≈ 重击的 68%，倒地是轻击的 2.4 倍 —— 层次清楚。
- **过渡**：回 idle 的每一步 ≤0.14 弧度 ✓ 没有跳变。
- 同一份探针里 `inClipMaxStepRad`（动作**自身**的单步最大跳变）：hit_light 0.005、hit_heavy 0.90、knockback 1.06、down 2.16 ——
  这是**受击动画本身的快节奏**（瞬间倒地/翻滚），不是过渡问题。若要连这个也压平，会削弱打击感，我没有动它。

### 3.3 修掉的那个真 bug：过渡结束条件
改动前，交叉淡入是**纯计时**结束（`blendT >= 1` 就停），而单帧限幅 0.6 弧度会让姿态落后于目标：
计时一到就不再混合，姿态**一帧内直接跳到目标**。实测 `down → idle` 那一帧跳 **2.229 弧度（128°）**。
现在结束条件是"**收敛**（与目标差 < 0.02）+ 计时 0.6s + **步数 60 步**"三重兜底 → 同一指标降到 **0.131 弧度**（17 倍改善）。

## 四、30 秒随机输入压测（`stress`，用 `__SS.gojo.dbg`）

样本：4386 帧（dt 3~8ms，游戏内部按固定步长跑多次 update）。

| 指标 | 值 | 判定 |
|---|---|---|
| 同名动作最长持续 | 660 ms（hit_heavy） | ✅ 无卡死 |
| 单次过渡最长耗时 | **477 ms** | ✅ < 600ms 上限 |
| 过渡步数上限 | 60 步（新增兜底） | ✅ 理论有界 |
| 单步最大姿态变化 | 0.6 rad（限幅生效） | ✅ |
| 连续处于过渡中的最长墙钟时间 | 3.2 s | ⚠ 见下 |
| 步态切换被冷却拦下的帧 | 594 / 4386（13.5%） | ✅ 属正常防抖 |

**关于"连续过渡 3.2 秒"**：逐帧样本显示该窗口里 name 一直在变（run→hit_light→hit_heavy…），
即被连段连续打断，每次都是**新的一次过渡**（每次 ≤0.477s），不是"一次过渡卡住不收敛"。
压测里 38% 的帧处于受击状态，这个数字是战斗强度造成的，不是动画缺陷。

**压测中发现并修掉的两处隐患**：
1. **重复请求把过渡清零**：`play("idle", {loop:false})` 这种"同名但 loop 参数不同"的重复请求，
   每帧都会重置 `curT/blendT/blending` → 姿态永远停在过渡起点（实测 blending 连续为真 5.3 秒）。
   现在同名 + 同为循环语义的重复请求直接忽略（真正的一次性动作仍可连续重触发）。
2. **dt 异常时过渡不收敛**：dt 为 0（暂停/固定步长累加器给 0）时，计时永远攒不满 0.6s。
   加了**步数兜底**（>60 步强制结束），保证过渡在任何 dt 下都有界。

**步态抖动**：`walk ↔ run` 来回切会把交叉淡入反复清零（实测切到 walk 后 blend 用了 1183ms 才到 1）。
现在两种切换用不同冷却：**步态之间 0.34s**（> 过渡时长 0.15s，保证每次都过渡完），**进出 idle 仍是 0.12s**（避免以站姿滑行）。
