# 第五轮：闪避 / 疾跑之后"动作僵硬不变"—— 4 个连环缺陷

用户反馈原话：「我点击闪避或者疾跑的时候 又回到之前动作僵硬不变的情况了」。
把手机档（844×390 + 真实触摸事件）跑起来逐帧采样才定位到，**这不是一个 bug，是四个叠在一起**。

## 缺陷 1：`play2()` 的早退条件漏了 `curLoop`

```js
if (name === curName && loop3) { ...; return; }   // ← 错
```
同一个动作名会先以 `loop:false` 播（起手），再被要求 `loop:true`（持续状态），
典型就是 `startInfinity()`：

```js
playAnim(pl.ctrl, "guard_infinity");   // loop=false
pl.ctrl.setGuard(true);                // play2(guard_infinity, {loop:true}) → 早退！
```

早退之后 `curLoop` **永远停在 false**，那个"应该一直循环"的动作播到 `dur` 就停住。
改成 `name === curName && loop3 && curLoop`。

## 缺陷 2：`setGuard(false)` 不收尾姿势

`guard_infinity` 是循环动作，关防御时只把 `guardOn` 置 false、不动画，
角色就一直保持防御姿势。补上：关闭时若不是在移动，就 `play2("idle")`。

## 缺陷 3：移动输入抢不动"循环中的非步态动作"（**这是用户直接命中的那个**）

`moveTowards()` 的接管条件原本是
`curName === "idle"|"walk"|"run"`，或者"一次性动作已经播完"。
**循环中**的 `guard_infinity` 两条都不满足 ⇒ 走/跑永远接管不了，
角色就以防御姿势在地面上滑行（用户看到的"僵硬不变"）。
改为：循环动作只要不在白名单里，一律允许步态接管（白名单实测下来是空的）。
防御的护盾/光环由 `guardOn` 驱动，不依赖骨骼姿势，所以接管动画不会丢视觉。

## 缺陷 4：步态切换在阈值附近抖动 ⇒ 每帧重新起手

`play2()` 每换一次名字都会把 `curT` 和 `blendT` 归零。`wantAnim` 在阈值附近来回跳时
（出招降速后 `want` 在 1.6~4.0 之间摆动），就变成"每帧重新起手"——混合权重永远停在 0，
骨骼几乎不动，看起来又是一次"僵硬"。
中间试过"目标稳定 0.1s 才切"，结果 `gaitHold` 被 `else` 分支每帧清零、**死锁**（实测抓到 1.4s 滑行）。
最终改成**切换冷却**（切一次冷却 0.12s），不会死锁；再加一条兜底：
只要这一帧有移动输入就**至少播走**，不允许以站姿滑行。

## 缺陷 5（顺手修掉）：出招期间全速滑行

模糊测试抓到"1 秒内滑行 3.4 米、大腿摆幅 0.03 rad"——按住方向键连打时，
角色以走/跑全速（4.8 m/s）滑行，腿上却停在出拳/踢腿的姿势里。
现在按招式阶段降速：起手 ×0.32、命中帧 ×0.18、收招 ×0.45。仍然能贴身追打，但重心被招式锁住。
