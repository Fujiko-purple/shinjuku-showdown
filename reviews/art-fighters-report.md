## 一、一句话结论

两个角色从"方块堆"变成**可辨识的人形格斗角色**：人形比例 7.8 头身、出招时光照不再糊成白剪影（反壳描边 + 墨线边缘压深）、
有贴地的接触阴影、有程序化五官与标志性特征（五条悟的黑眼罩 / 六眼 / 高专制服，宿傩的和服 / 黑色纹身 / 真身四臂）。

## 二、改了什么

### 1. 人形比例与骨架装配（`buildRig` 整段重写）
- 身高 **1.88m / 7.8 头身**，肩宽 ±0.20m（五条悟）/ ±0.212m（宿傩，更壮），腰窄臀收，腿长占身高 52%。
- **脚底落在 y=0**：基线角色悬空 6cm，实测 `Box3` 最低点现在 **-0.014m**（鞋底压进地面 1.4cm，视觉上是"踩实"）。
- 四肢用 `limbY()` 旋转体（两端浅圆角），相邻肢段互相咬合，**关节处不再"掐腰"成一串珠子**。
- 躯干用 `latheY()` 旋转体做出肩→腰→臀的人形剪影；头用"颅骨 + 颧骨 + 下颌"三段椭球。
- 骨骼名与层级**完全没动**（`BONES` 数组原样），`createFighter` 对外接口原样（`bones/handR/handL/chest/handR2/handL2/setMode/setBlindfold/...` 全部保留）。

### 2. 顶点色合并：draw call 砍掉一大半
- 新增 `mergeParts()`：同一个骨骼上的所有零件（头发 20 根锥体、纹身线、关节、靴子…）合并成**一个带顶点色的网格**，
  用一张 `vertexColors` 材质画完多种颜色。
- 五条悟 61 个网格 / 17.4k 面，宿傩 70 个网格 / 19.9k 面（含描边壳）——基线是各 75 / 95 个网格。
- **`mergeParts` 做了防御**：坏零件只 `console.warn` 跳过，绝不让一个零件把整局游戏带崩（这是之前那次启动崩溃的根因）。

### 3. 脸部（P0，本轮重点）
- 贴图从"正面一块平面"换成 **球面贴片 UV**：`spherePatch()` 在椭球表面切一块壳，
  用 512px canvas 贴图（`texGojoFaceBlind` / `texGojoFaceEyes` / `texSukunaFace`），
  因为画在球面上，**天然贴合头型**，从任何角度看都不会露出"贴纸浮在脸上"。
- **五条悟**：黑眼罩是一条球面带（布面压光 + 上下缝线 + 针脚 + 褶皱），眼罩下面是鼻梁暗侧 / 鼻头投影 / 薄唇 / 下颌明暗；
  `setBlindfold(false)`（觉醒态）切换第二张贴图 = **青色六眼** + 白色睫眉 + 眼周加法辉光（两片小面片，径向渐变淡出）。
- **宿傩**：猩红眼 + 深眼窝 + 眉上粗横纹 + 眼下弧线 + 颊侧竖纹 + 下巴两侧短纹 + 冷笑嘴角；
  觉醒态额外显示**额上第二对眼**（真身）。
- 头身贴合：脸贴片半径取颅骨的 1.055 倍，配合 `polygonOffset` 贴片模式，不 z-fighting。

### 4. 光照与剪影（基线最严重的问题）
- **反壳描边**（inverted hull）：每块主要体块套一层放大 5.5%~7% 的 BackSide 深色壳，
  **任何背景上剪影都是深色描边**，不再糊成白剪影。中/高画质开启，低画质关闭（省 draw call）。
- **墨线边缘压深**：高次菲涅尔（`pow(1-ndv, 3.2)`）只在真正贴边的位置压墨色，做出日式卡通的分界线。
- **主光改成"肖像光"**：从"左上后方"（原本完全背光，正脸全黑）改为**左上前方**，
  背光面靠半球补光和边缘光托形；夜景里角色的脸终于看得见。
- **色阶掺 30% 平滑**：保留 3 段卡通色阶，但脸上不再出现一道生硬的分界线。
- **受击闪白重写**：原来 `mix(col, vec3(1), flash)` 会把整个角色糊成纯白剪影；
  现在只在**亮部与轮廓**爆亮，暗部（制服/裤子）保留本色，受击时形体依然读得出来。
- **加了输出色彩空间转换**（`colorspace_fragment`）：在此之前角色材质不走 sRGB 输出，比城市场景暗一大截。

### 5. 接触阴影（P1）
- 脚下两层：**深色软影**（径向衰减贴图，1.4×1.08m，透明度 0.8）+ **极淡加法光池**（0.66×0.52m，透明度 0.13）。
  深色沥青上单靠黑影看不出来，那层光池才是"踩在地上"的观感来源；亮色路面（斑马线）上黑影会明确读出来。
- **随跳跃变化**：起跳时影子缩小、变淡（`poseBuf.__rootY` 驱动），落地压回 —— 重量感的关键。
- 阴影不计入受击闪白/咒力发光（材质不是 toon 材质），但会跟着 `setScale` 缩放。

### 6. 胶囊罩（Lead P0）—— 已彻底删除
- `buildRig` **不再创建 `shellMesh`**（`const shellMesh = null`），所以播片/战斗里都不可能再出现那个"福尔马林胶囊"。
- 术式状态改用两件事表达：**描边壳整体亮成咒力色**（`uRimStrength` 0.34 → 1.0）
  + **脚下光环放大到 3.4 倍**（领域态）。保留 `setAura/setDomained/setGuard` 接口语义不变。

### 7. 性能与降级
| 项 | 实测 |
|---|---|
| dist/新宿决战.html 实机（1600x900，D3D11） | **draw calls 193 / 三角面 123k / 着色器程序 52** |
| 角色三角面 | 五条悟 17.4k、宿傩 19.9k（红线：桌面 ≤250k、手机 ≤120k） |
| 角色网格数 | 61 / 70（含描边壳；低画质关描边后各减 ~11） |

`QUALITY3` 三档全部可用：`low` 关描边/布料/纹样、径向段数 7、贴图 128；`medium` 开描边不开"全描边"、贴图 256；`high` 全开、贴图 512。接触阴影**三档都保留**（只降贴图分辨率），因为它是重量感的主要来源。

## 四、自己玩了一遍之后，还剩下的问题（不粉饰）

1. **脸是"画上去的"，不是雕出来的**：贴图贴在椭球面上，极近特写（<0.5m）能看到球面网格的棱和 UV 拉伸，
   五官是平面的而非立体结构。要彻底解决需要真正的头部雕刻（blend shape / 顶点塑形），本轮没做。
2. **头发还是锥体堆的**：远看/中景没问题（发冠有蓬松感、有方向），贴脸看能明显看出是一根根圆锥。
   想再上一档需要发片（hair cards）而不是圆锥。
3. **接触阴影在纯黑沥青上依然看不见**：只在亮色路面（斑马线、人行道）明确。这属于物理正确但观感吃亏的情况，
   目前靠脚下那层很淡的加法光池找补；如果 world-city 把路面提亮，这一条会自然解决。
4. **手指/鞋型是简化的**：手是"掌心 + 指团"两段体块，没有五指；靴子/草鞋是圆角块。中景够用，特写不够。
5. **宿傩衣服的纹样偏"织纹"**：为了不糊成棋盘格，把和服纹样压得很淡，近看稍显素。
6. **六眼态的辉光是两片正面小面片**：极端侧脸角度下会看到面片变薄（不在正对视线时会变窄）。
7. **实机里角色仍然偏小**（相机是 camera-ui 的写域）：本模块只负责角色本身，角色占屏比等相机调整后会更明显。

## 七、P0 回归修复（用户反馈"肢体移动非常诡异"）

### 现象
用户反馈：行走 / 打斗 / 放技能时角色形变离奇。Lead 抓到的连续帧里五条悟出拳时像"一片青色影子摊在地上"、走路"腿部糊成一坨"。

### 根因（我自己的错）
上一版为了"更英雄的比例"，**擅自改长了肢段、改了肩点高度**：
`core 0.12`（原 0.1）、`neck 0.20`（原 0.235）、`shoulder ±0.20 / y0.155`（原 ±0.185 / y0.19）、
`thigh -0.055 / shin -0.455 / foot -0.425`（原 -0.1 / -0.425 / -0.418）、
大腿/小腿几何 0.46/0.43（原 0.425/0.418）。

**但 `POSE_LIB` 里 30 组动画、上千个角度全是按原版骨骼长度调的**。骨骼一变长：
- 走/跑/下蹲时**脚直接陷进地面**（原版脚本来就悬空 6cm，是"错有错着"地留了余量）；
- 膝、肘的折叠量对不上，腿在低分辨率下糊成一坨；
- 手臂的摆动幅度按原肩高算，肩点一挪就显得横伸。

### 修法
**把骨骼偏移量与肢段长度全部还原成原版数值**，只保留一处改动：
`hips` 从 1.06 降到 1.00 —— 这才是修掉"悬空 6cm"的正确做法（整体下移，而不是把腿拉长）。
还原后脚踝在 y=0.057，鞋底正好压在地面上。

### 验证（客观数据，不是"我看着行"）
观测台逐姿势量角色包围盒最低点（不含阴影贴片）：

| 姿势 | 最低点 y |
|---|---|
| idle | -0.022 |
| walk t=0/0.25/0.5/0.75 | -0.021 / -0.030 / -0.003 / -0.046 |
| run t=0/0.3/0.6 | -0.021 / +0.016 / -0.006 |
| punch / kick / jump / land / hit_heavy | -0.012 / +0.008 / +0.016 / +0.016 / +0.016 |

全部在 ±5cm 内 → **所有动作里脚都踩在地上**，不再有"融化"或"漂浮"。

### 顺带修掉的两个观感问题
1. **反壳描边偏心**：描边壳原来是**绕骨骼原点**放大的，几何一偏心壳就从模型里穿出来（身上出现一道道虚线）。改成**绕几何自身中心**放大。
2. **整体发青、形体被"镶边"压平**：本体边缘光 0.30→0.22、描边壳的咒力色混入 0.34→0.22，角色的明暗层次回来了（近景能看到制服的褶皱面）。

### 复验截图
- `shots/zoom-gojo-idle0.png` —— 实机静止：手臂自然下垂、头正、形体结实（**这是修复后最直观的一张**）
- `shots/zoom-gojo-walk3.png` / `shots/anim-fix2-walk3.png` —— 实机奔跑：前倾、迈步、摆臂，人形完整
- `shots/anim-fix2-punch3.png` —— 实机连段命中帧

> 说明：`combo_finish` 这套连段终结技**本身就是"双臂平挥"的旋转攻击**（POSE_LIB 里 `upperArmR.z=1.56`、`upperArmL.x=-1.551`），
> 在 800x450 的低分辨率下容易被误读成 T-pose。这是原版就有的动作设计，我没有改它；
> 但把描边和边缘光调淡之后，这个动作的"躯干带动手臂"关系现在能看出来了。

## 八、第三轮：操作手感与肢体僵硬（用户第二次反馈）

用户原话："肢体和操作手感完全不契合…人物肢体都是僵硬的，不符合正常的人体生理视觉感"。
下面逐条给结论与**改前/改后的实测数字**（都不是"我觉得好点了"）。

### 方向 1：跟手度 —— 有结论：**原来确实没有**

用 `_tools/_gen/drive.mjs` 直接驱动 `moveTowards`（绕开战斗 AI 干扰），逐帧记录位移：

| 指标 | 改前（原版基线） | 改后 |
|---|---|---|
| 起步第 1 帧位移 | **-0.0867m（一帧就到全速 5.2m/s）** | **-0.0205m（全速的 24%）** |
| 第 4 帧累计 | -0.3467m（线性） | -0.1496m |
| 第 10 帧累计 | -0.8667m（线性） | -0.5870m |
| 松手后滑行 | **0（瞬间钉死）** | **-0.157m（有惯性，约 16cm）** |

改动：`moveTowards` 内部改成速度指数逼近（`tau = 0.085s`，冲刺 0.055s），`update2` 在"本帧没收到移动指令"时按 `tau=0.062s` 衰减并继续位移。
**手感上就是从"瞬移方块"变成"起步要半只脚、松手会滑半步"。**

转身（`_tools/_gen/turn.mjs`，调 `faceTo` 掉头 180°）：

| 指标 | 改前 | 改后 |
|---|---|---|
| 前 5 帧每帧转角 | 1.8° / 1.3° / 5.1° / 4.3° / 1.7°（无规律） | **1.1° / 2.1° / 3.3° / 3.4° / 4.6°（干净的加速段）** |
| 后 5 帧每帧转角 | 4.6° / 3.9° / 5.4° / 2.0° / 3.9°（到最后一帧还在快转） | **2.5° / 1.9° / 0.9° / 1.9° / 0.9°（收得住）** |

改动：转身改成**角速度限幅 + 平滑**（原来 `min(|diff|, d*9)` 是匀速硬转、说停就停），
并且**转弯时上半身先压肩侧倾**（`core.rotation.z`，最大 ±0.26rad）。

### 方向 2：动画混合 —— 有结论：**原来是硬切，而且很夸张**

`_tools/_gen/feel-probe.mjs` 逐帧采样 `upperArmL.rotation.x`，测"切换动作那**一帧**的跳变量"：

| 指标 | 改前 | 改后 |
|---|---|---|
| 动作切换帧的跳变 | **2.532 弧度（145°）** | **0.428 弧度（24°）—— 平滑了 6 倍** |

改动：新增**姿态交叉淡入**——切换动作时以"上一帧真正贴到骨骼上的姿态"为起点，
在 0.1s（攻击）/ 0.14~0.2s（位移/待机）内用 smoothstep 过渡到新动作。
> 中间踩过一个坑：一开始用 easeOut 做淡入曲线，结果**第一帧就吃掉 42%**（该帧跳变反而有 1.0 弧度），换成 smoothstep 后首帧只走 7%。

### 方向 3：生理合理性 —— 有结论：**走路的骨盆几乎是死的**

逐帧统计行走时的骨骼运动幅度：

| 指标 | 改前 | 改后 | 说明 |
|---|---|---|---|
| 骨盆左右倾（幅度） | 0.0061 rad (0.35°) | **0.056 rad (3.2°)** | 提高 9 倍 |
| 骨盆旋转（幅度） | —— | **0.16 rad** | 新增：骨盆随步伐旋转 |
| 肩带反向扭转 | 0.28 rad | 0.14 ~ 0.22 rad | 改为**与骨盆反相**（原来只是整体摆动，不是反扭） |
| **头部偏摆** | 0.20 rad | **0.040 rad** | 头**不再跟着躯干摇**（头部稳定化） |
| 摆臂幅度 | 1.70 rad | 0.81 + 程序化叠加 0.3×速度系数 | 摆臂随速度增长 |

新增的**程序化行走层**（在姿态采样之后叠加）：
骨盆上下起伏 / 左右倾 / 旋转、肩带反向扭转、摆臂随速度、
**头部稳定**（抵消躯干的扭转与侧倾——这是"活人感"最便宜的一招）；
走/跑时相位直接取自动作剪辑（`curT/dur`），**骨盆起伏与脚步严格同相**，不会各走各的。
另有**加减速前后倾**（加速时上半身前压、急停后仰，`leanPitch` 最大 -0.13~+0.17rad）。

### 关于"角色变小"的适配
相机已拉到 16.1m（角色占屏 **16.4~16.9%**，`_tools/acceptance.mjs` 实测），
所以程序化动作的幅度是**按小尺寸可读来定的**：骨盆倾 3.2°、扭转 9°、摆臂叠加 17°，
比"特写好看"的幅度大一档。特写时也不至于夸张到失真。

## 九、第四轮：小尺寸下的步态可读性（Lead 量化诊断）

诊断结论（Lead 给的）：动画在播，但相机拉远到角色占屏 **16.6%（1600x900 下约 130px，腿约 50px）** 后，
按近景调的腿部摆幅在屏幕上只剩"几个像素"，肉眼读不出在迈步。

**先补了一把客观尺子**：`_tools/_gen/leg-pixels.mjs` —— 只测"膝盖相对髋关节"的运动并投影到相机平面
（与相机跟随/位移完全无关），再折算到"角色 130 像素高"下的像素数。

### 怎么改的
1. **步态夸张系数 `GAIT_AMP`（编译期）**：在 `createSampler` 编译 walk/run 时，
   对**作者显式写过值的骨骼通道**按倍率放大（大腿 1.55~1.6、小腿 1.45~1.5、脚 1.3、摆臂 1.5~1.55、髋/躯干 1.2~1.7、根骨起伏 ry 1.7~1.8）。
   只放大显式通道，不碰采样器的补帧逻辑；冲刺档比走路再大一档。
2. **程序化层加码**：骨盆起伏改成**只往下沉 6.2cm/步**（不是上下浮动）—— 这样绝不会把脚抬离地面，同时每次落脚都有"压一下"的重量感；
   骨盆左右倾 0.115、骨盆旋转 0.19、肩带反相扭转 0.26、摆臂叠加 0.38（都随速度缩放）。
3. **冲刺前倾**：速度超过 4 m/s 后上身逐渐前压（最多 0.34 rad ≈ 19°），小尺寸下"在跑"这件事一眼可见。
